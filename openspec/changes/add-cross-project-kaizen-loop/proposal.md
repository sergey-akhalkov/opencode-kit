## Why

The kit can record explicit workflow complaints, but it has no single lifecycle that reliably preserves long-session reflections, catches completed OpenSpec work before the session ends, routes recurring cross-project friction, and closes stale entries. The current Markdown feedback ledger demonstrates the gap: captured items remain open even after corresponding behavior changes, while short completed changes can finish before compaction and long sessions can lose useful observations unless each compaction preserves them.

## Outcome Capsule

- **Outcome**: Every installed kit session can submit bounded structured Kaizen signals to one machine-local cross-project inbox; long root sessions emit and persist a signal block at each compaction; a complete OpenSpec archive opens and closes a separate non-blocking harvest checkpoint; and an `opencode-kit`-rooted triage command can disposition a bounded pending set and create at most one ordinary evidence-bounded OpenSpec proposal without directly mutating another project.
- **Operating Envelope**: The loaded global `session-env` plugin on one local workstation, canonical Git worktree identity reduced to a privacy-safe project ref, at most 2,000 immutable signal records and 8,000 decision/checkpoint events, 16 KiB per signal and 4 KiB per lifecycle event, zero to three signals per compaction or archive harvest, and at most 25 pending signals per explicit triage invocation. The feature writes only beneath the platform OpenCode data root, reads only the newest root-correlated compaction summary or explicit tool input, stores no transcript or absolute-project reverse map, and performs no remote, provider, project-worktree, or external-service operation from plugin code.
- **Non-Goals**: Detecting every human irritation, reading or retaining raw session transcripts, mining arbitrary tool output, semantic scoring in deterministic code, automatic code fixes, automatic project-memory promotion, background scheduling, unattended campaigns, remote issue creation, direct writes from consumer projects into the `opencode-kit` worktree, multi-repository transactions, cross-machine synchronization, or replacing OpenSpec, project memory, session delivery context, Codebase Memory, Serena, or the completion guard.
- **Non-Deferrable Invariants**: Archive success and Kaizen harvest status remain separate dimensions; a harvest failure never reverses or disguises a completed archive and remains a visible repair gap; compaction and archive always emit a schema-valid empty-or-populated signal envelope or a visible capture gap; persisted payloads contain only closed-schema redacted signals and privacy-safe refs; concurrent writes are append-only and fail visibly at capacity; one signal store is authoritative while Markdown feedback is an idempotent fallback/import source; triage never invents source-project facts, protected decisions, or implementation authority; unrelated plugin, compaction, archive, and project-memory behavior remains available when Kaizen capture fails or is disabled.
- **Observable Proof**: Through a copied and installed `session-env` entry point against two disposable Git worktrees and one isolated OpenCode data root, explicitly report a signal, observe project-isolated source refs in one shared inbox, compact a synthetic long root session and persist only its valid bounded signal envelope, exercise missing/malformed/duplicate compaction output as visible capture gaps without transcript retention, complete an OpenSpec archive and observe `harvest-pending` close as `captured` or `no-signal`, interrupt post-archive harvest and observe a durable repair gap while archive status remains `archived`, import one legacy Markdown entry idempotently, disposition a bounded set, and create one valid proposal only from an `opencode-kit`-rooted triage session. Verify fixed capacity, concurrent exclusive creation, redaction, opt-out, restart behavior, no worktree mutation outside the explicitly requested proposal, and no plugin-originated provider or network call.
- **Material Residual Risks**: The supported OpenCode version may not expose a stable correlation between `session.compacted` and the generated summary; model-generated signal quality can omit or misclassify friction; known redaction patterns cannot prove absence of every unknown secret format; a local inbox without the deferred scheduler can retain visible pending items; default-on local capture increases machine-local state; and active changes currently overlap compaction, instruction, runtime-profile, and plugin composition surfaces.
- **Stop Line**: Finish one authoritative bounded inbox, explicit capture/status/triage tools, core/all profile exposure, strict compaction signal emission and readback, non-blocking archive harvest checkpoints, Markdown fallback/import, one manual kit-rooted proposal path, privacy/failure controls, focused validation, and installed-entry-point proof. Stop before scheduler or campaign integration, automatic tool-failure mining, project-memory writes, remote submission, cross-machine sharing, multi-repository mutation, semantic deterministic grouping, generalized issue management, or autonomous implementation.

## What Changes

- Extend the existing `session-env` composition owner with a self-contained Kaizen module and bounded explicit report, status, checkpoint, and triage tools backed by one machine-local append-only store.
- Change the managed compaction reflection contract to always emit a strict zero-to-three-signal envelope; capture only the newest root-correlated envelope after compaction and persist a visible gap when correlation or validation fails.
- Extend canonical complete-archive orchestration with a pre-archive `harvest-pending` checkpoint, post-archive `captured` or `no-signal` closure, `archive-failed` closure after helper failure, and a projected `repair-gap` for an open checkpoint after successful archive while preserving archive status independently.
- Retarget `complain` to the authoritative Kaizen inbox when available, retain Markdown as a fail-visible fallback, and import fallback entries idempotently so two live backlogs cannot drift.
- Add global status and triage commands, expose the required surface in core/all runtime profiles, and allow proposal promotion only from a verified `opencode-kit` root with one bounded outcome and proof boundary.
- Reuse the existing OpenCode data-root, redaction, canonical-root, exclusive-create, copied-plugin proof, and operation-gate patterns without changing project-memory records or introducing a generic persistence framework.
