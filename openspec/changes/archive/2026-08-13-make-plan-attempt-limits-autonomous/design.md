## Context

The kit already distinguishes user-owned outcome/protected boundaries from orchestrator-owned task and path inventory. It also says that internal revisions and process counters are not owner blockers. The missing connection is explicit treatment of mutable OpenSpec attempt ceilings and stop lines after a causal correction: a literal one-attempt rule can be mistaken for immutable user scope even when it was authored only as a process safeguard and all accepted semantics remain unchanged.

This change affects loaded global authority, conditional Material guidance, OpenSpec entry points, reusable templates, the hidden completion arbiter, normative specs, and exact contract markers. Historical archived changes remain immutable evidence and are not runtime authority.

The fidelity ladder is: deterministic contract/static validation -> fresh configured OpenCode session over paired synthetic scenarios -> no physical/live product operation. The current rung is instruction/source evidence. The next real boundary is a fresh primary session loading the candidate global config. Existing standing configured-provider authorization covers that bounded synthetic inference; no protected product action is involved.

## Goals / Non-Goals

**Goals:**

- Make the main session explicitly responsible for adapting plans, task inventories, OpenSpec artifacts, revision/candidate labels, attempt limits, and process stop lines when evidence shows that adaptation is necessary to complete the accepted outcome.
- Prevent fake owner choices such as "extend the current change or stop" when only process bookkeeping changes.
- Keep the underlying protected action independently gated by authority, `Live-Attempt Gate`, safety, restoration, cleanup, identity, and evidence requirements.
- Make the distinction observable through deterministic markers and a paired fresh-session behavior proof.

**Non-Goals:**

- No automatic expansion of accepted user-visible outcome or operating envelope.
- No weakening of public API/protocol, persisted-data, security/privacy/authorization, legal/policy, remote/destructive, cost, release, or manual hardware boundaries.
- No permission to retry unchanged strategies or bypass failed/unknown offline replay.
- No generic lifecycle engine, semantic classifier, or new reusable implementation.
- No mutation of archived OpenSpec history.

## Decisions

### 1. Classify process controls by semantics, not by artifact location

Plans, tasks, OpenSpec text, revision names, attempt counts, and stop lines are implementation controls unless changing them also changes the accepted outcome, operating envelope, non-deferrable invariant, material risk decision, or protected-boundary authority. Main updates the smallest coherent set and records why.

Alternative: treat every normative spec sentence as owner scope. Rejected because agent-authored process safeguards would permanently prevent correction and force owner approval for implementation bookkeeping.

### 2. Separate permission to update a plan from permission to execute its next action

Updating a one-attempt limit never grants authority for the successor operation. Before a repeated external, physical, costly, destructive, or otherwise protected run, the existing gate still requires causal change, preserved bundles, terminal offline replay, clear unlock, authority for the underlying action, safety/restoration readiness, and expected evidence.

Alternative: exempt corrected pre-boundary failures from live-attempt controls. Rejected because a later run may still reach the controller or external side effects.

### 3. Make autonomous successor behavior mandatory when all gates are satisfied

If accepted semantics and underlying action authority already cover the successor, the gate is clear, and the strategy has materially changed, main must update the artifacts and continue. It must not ask whether to expand the change, create a revision, raise an attempt count, or proceed with process continuation.

Alternative: merely permit autonomous updates. Rejected because the reproduced failure came from choosing a needless question despite existing permissive wording.

### 4. Keep one canonical rule and proportional mirrors

`global/AGENTS.md` owns the complete distinction. `change-ready-sdlc`, OpenSpec propose/apply/archive, project templates, and the completion arbiter carry only role-specific operational wording. Exact contract markers enforce the positive autonomy phrase and protected-action separation without trying to infer semantic necessity.

Alternative: add only a personal preference. Rejected because the behavior is broadly useful lifecycle policy and must survive installation into other projects.

## Risks / Trade-offs

- **Over-broad autonomy could authorize a protected operation** -> Pair every autonomy marker with explicit separation of artifact updates from underlying action authority; retain all existing live-attempt gates.
- **Static markers can pass while behavior remains hesitant** -> Run paired fresh-session scenarios and inspect whether `question` is absent/present at the correct boundary.
- **Instruction duplication can increase context and drift** -> Keep complete semantics in global authority and use short mirrors; validate inventory and configured surfaces.
- **OpenSpec changes could rewrite accepted semantics accidentally** -> Require traceability to unchanged outcome/invariants and treat any semantic/protected-boundary change as an exact owner decision.

## Migration Plan

1. Add normative delta specs and focused deterministic markers.
2. Update canonical and proportional runtime surfaces in one candidate.
3. Run source/contract validation, then invoke a fresh configured OpenCode primary session with the paired scenarios.
4. After MVP proof and accepted-scope completion, use fresh test-only SDET for the smallest missing critical regression oracle, then run complete validation.
5. Restart/new sessions load the changed config-time artifacts; the current session remains baseline evidence.

Rollback is source-only: revert this change's candidate paths. No persisted product data or external state is changed.
