## Context

See `proposal.md` for the routing problem and MTAET-001 claim boundary. Current loaded Team Advice authority has two useful but poorly separated paths: an objective trivial owner-local bypass, and a broad non-trivial-root advisor trigger. The first is too narrow; the second serializes an advisor call even when one current owner, selected route, and representative proof are already established. An earlier combined plan replaced that with the circular sentence that main did not need advice to decide advice had no value. This design instead makes direct eligibility a conjunction of current observable mission facts.

Team routing is independent from artifact-shape/risk semantics owned by archived `streamline-ordinary-small-closure` (SOSC). It is also independent from OPDC, LFTD, CCO, Change-Ready, and exact Practice Owner routing. OPDC, LFTD, CCO, and SOSC are archived in the selected order; the current ownership inventory resolves every declared direct pair and selects this change as the mutation-enabled owner while the dependent PCR change remains disabled.

The current fidelity rung is conflict-free transferred ownership and existing provider-free STA-001 behavior. The next real boundary is one provider-free objective-predicate fixture, followed by one installed direct scenario. No external, remote, deployment, install, credential, destructive, or consumer-project effect is authorized. Configured proof uses current-run status, stdout/stderr, events, effects, diagnostics, and cleanup only; it SHALL NOT retain a replay corpus or repository evidence bundle. Proof-owned roots, sessions, processes, and temporary output are automatically cleaned.

## Goals / Non-Goals

**Goals:**

- Define one objective complete direct-route predicate from current evidence.
- Activate one advisor map only for a concrete unresolved team-selection fact.
- Make `direct` mean advisor omission only, with no lifecycle or safety bypass.
- Preserve exact Practice Owner activation without advisor discovery.
- Keep catalog access technically fail-closed by attributable advisor/root identity and catalog failure scoped, while preserving the current unrestricted host permission policy and role-text authority boundary.
- Preserve mission continuity and reconsult only after material topology change.
- Prove the shortest direct path before positive advisor and bypass controls.

**Non-Goals:**

- Do not remove, merge, or add an advisor, Practice Owner, worker, reviewer, or routing registry.
- Do not alter OpenSpec artifact profile/risk semantics, LFTD, OPDC, CCO, Change-Ready, substitution, proof, or protected-action policy.
- Do not implement deterministic task classification, ranking, scoring, or expert selection.
- Do not optimize every specialist call or broaden the catalog projection.
- Do not retain configured-run transcripts, replay bundles, or evidence archives.

## Decisions

### 1. Direct eligibility is a complete conjunction of current facts

Main may omit the advisor only after bounded foraging establishes all seven facts:

1. one known semantic owner for the accepted next result;
2. one already selected execution route;
3. one representative proof boundary;
4. no unresolved maintained-route choice;
5. no unavailable required capability;
6. no unique independent-evidence need whose package can change the next action;
7. no unresolved delegation or isolation boundary.

Facts must be current for the accepted outcome, candidate/worktree, environment, and next dependent action. Unknown, unsupported, conflicting, or stale facts do not satisfy the predicate. Task size, file count, local reversibility, model confidence, or the sentence "no advisor is useful" is never a substitute.

This is an instruction-level semantic predicate, not a deterministic router. Stable fixture inputs may record each fact explicitly so evaluators can compare expected and observed events; helper code does not derive the facts from prose or repository shape.

Alternative rejected: keep only the objective trivial bypass. It pays the advisor for known non-trivial direct work. Alternative rejected: let main decide whether advice adds unique value without explicit facts. That recreates circular self-exemption.

### 2. Advisor activation is tied to the unresolved selection fact

One advisor call is justified only when a concrete uncertainty remains after foraging:

- competing maintained routes with different value or boundaries;
- an exact required capability whose availability or owner is unresolved;
- a unique independent-evidence package whose selection changes the next accepted action;
- an isolation or delegation package whose value or boundary is unresolved.

The engagement map must answer that fact and may return `main-alone`. It does not launch specialists, authorize mutation, make product decisions, or become a lifecycle phase. The advisor is not called merely because work is non-trivial, a specialist exists, or a future review might be useful.

Alternative rejected: mandatory advisor with cached `main-alone`. It still pays the serial first call and makes cache validity another lifecycle state.

### 3. Direct is an advisor-state value, not a universal exemption

The routing decision is orthogonal to every other maintained contract:

| Current fact | Required route |
|---|---|
| Complete direct predicate, no other trigger | Main omits advisor and executes the selected route. |
| Exact Practice Owner trigger, no team-selection uncertainty | Main invokes the owner directly and omits advisor. |
| Material trigger with complete team route | Main omits advisor and loads Change-Ready before mutation. |
| LFTD, OPDC, CCO, OpenSpec, substitution, proof, validation, or safety trigger | Main omits or uses advisor according to team facts, then independently follows the matched contract. |
| Concrete team-selection uncertainty | Main obtains one advisor map before package-dependent action. |

No route can use `direct` as evidence that another trigger is absent, satisfied, or authorized. Focused bypass fixtures must fail when both advisor and the independently required route are omitted.

Alternative rejected: copy every downstream contract into Team Advice prose. That would duplicate semantics and drift. The Team Advice owner names non-bypass boundaries and leaves detailed rules with their canonical owners.

### 4. Exact Practice Owners remain directly discoverable

The registered owner mapping already determines exact practice triggers. When one trigger matches and no team-selection uncertainty exists, main invokes that owner directly. Team advice is neither a registry lookup nor a prerequisite for owner activation. If several expertise surfaces create an actual package-selection question, the advisor may recommend the smallest map while owner semantics remain canonical.

This avoids routing every material practice through another model call and preserves the separate outcome-readiness challenge required for decision-material planning.

### 5. Catalog access and failure remain scoped

The current privacy-safe catalog is reused under the current unrestricted host permission policy. The advisor remains role-bounded and non-authorizing even though the local runtime technically grants broad tools. Only an attributable advisor child with a resolvable parentless root may receive `specialist_catalog` data. Deterministic tooling validates schema, availability references, stable ordering, privacy, caller/root identity, the explicit unrestricted runtime identity, and required role prohibitions. It does not evaluate direct eligibility or choose a team.

If the catalog is unavailable, only the accepted item that requires a catalog-backed package choice becomes unknown or blocked. Any independent item with a complete direct predicate continues. A mission-wide `Team Advice: unknown` state is not created when no advice exists.

### 6. Advice state begins only after advice and survives ordinary continuity

`Team Advice State` is absent before an advisor call. After advice, compaction preserves only advisor task/candidate/catalog refs, main disposition, active and terminal packages, pending activation facts, specialist liveness, integration state, unavailable material capabilities, and one reconsultation condition. Propose-to-apply transition, compaction, package completion, or ordinary progress does not create a new advisory episode.

Reconsult once only after a material change in outcome, evidence, candidate, catalog, integration boundary, ownership, or conditional activation. This reuses current continuity rather than adding a cache or team ledger.

### 7. Reuse STA-001 and prove direct before broader controls

The automation dividend extends the maintained STA-001 seed/evaluator and exact catalog/routing validators. One direct member supplies all seven facts and expects zero advisor/catalog calls. Positive members each omit or contradict one material fact and expect one attributable advisor. Bypass members expect zero advisor calls plus the exact independently required route.

Proof order:

1. Provider-free predicate, catalog attribution/privacy, runtime-permission identity, role-boundary, and deliberate-red controls.
2. Actual installed direct scenario with zero advisor/catalog calls, representative runtime proof, and cleanup.
3. Installed competing-route, unavailable-capability, independent-evidence, and isolation controls.
4. Exact Practice Owner and Material/LFTD/OPDC/CCO/OpenSpec non-bypass controls.
5. Mission continuity, catalog outage scoping, and finite MTAET-001 readback.

The configured catalog-outage member substitutes only the generated proof copy's catalog API handle with `null`, reaching the production plugin's existing `catalog-api-unavailable` branch. Production source and all other loaded identities remain unchanged. Component tests establish the branch's `unknown`, empty-entry, and privacy-safe result; the configured member separately observes advisor disposition, the independent direct sibling, effects, and cleanup. The maximum substitution claim is this one API-unavailable branch in the recorded model/profile/source/environment, not arbitrary catalog faults or general equivalence.

After a failed configured run, inspect exact invocation, identity, exit status, stdout/stderr, events, effects, and cleanup. Another equivalent call requires a causal mechanism change or exact missing observation. Current-run diagnostics determine the decision; no retained replay path is created.

### 8. Exact ownership follows all predecessors

This change is `mutationEnabled=true` after OPDC, LFTD, CCO, and SOSC archived in order with terminal writers and exact transfers. Apply still rereads current manifests, source/runtime identities, and scoped diffs before production mutation. The ownership manifest declares direct dependencies on every overlapping predecessor because transitive dependencies do not resolve pairwise inventory conflicts. Exactly one active change may mutate each root.

Alternative rejected: edit apparently free advisor files while shared loaded-main or proof roots remain owned elsewhere. That would create a mixed candidate and make installed routing evidence uninterpretable.

## Risks / Trade-offs

- **[Model asserts facts without evidence]** -> Predicate requires current observed facts; fixtures supply explicit facts and reject unsupported direct disposition.
- **[Advisor is under-called]** -> Positive controls isolate each unresolved selection class; omission fails independently of latency or context gains.
- **[Advisor is over-called]** -> Complete-direct member requires zero advisor/catalog calls and no empty Team Advice state.
- **[Direct bypasses another contract]** -> Dedicated controls require the exact Practice Owner/Material/LFTD/OPDC/CCO/OpenSpec/substitution/safety route even with zero advisor calls.
- **[Catalog outage broadens]** -> Scope failure to the package-dependent item and retain an independent direct sibling control.
- **[Continuity causes stale advice]** -> Preserve one explicit reconsultation condition and current candidate/catalog/source refs; material topology change invalidates only dependent advice.
- **[Proof becomes retained evidence infrastructure]** -> Use current-run diagnostics and automatically cleaned temporary roots; retain only reviewed project-native seed data.
- **[Active ownership order changes]** -> Keep mutation disabled and reread every predecessor before exact transfer.
- **[Finite population is overgeneralized]** -> Preserve MTAET-001 maximum claim and unresolved observations.
