- **Objective:** Ensure the agent interrupts slow work before the user has to ask why progress is taking so long.
- **Approach:** Trigger reflection after a fixed elapsed interval or while an OpenSpec `N/M` task count remains unchanged.
- **Evidence:** Existing project evidence includes legitimately slow real boundaries, coarse tasks containing multiple dependency failures, and fast repeated invalidation loops. The global principles reject proxy optimization and require observed bottleneck evidence.
- **Outcome:** Rejected.
- **Reason:** A universal clock or checkbox threshold would over-trigger on necessary advancing work, miss fast rework amplification, and optimize response cadence rather than outcome progress.
- **Do Not Repeat:** Do not use elapsed time, turn count, token count, or unchanged task count as a sufficient delivery-drag classifier.
- **Evidence-Based Retry Condition:** Reconsider only if current matched runtime evidence proves one bounded threshold improves outcome progress across unrelated task classes without false positives or proxy pressure.
