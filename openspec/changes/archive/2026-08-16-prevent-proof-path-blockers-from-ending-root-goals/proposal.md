## Why

An OpenCode session can correctly refuse a protected action yet still end the user's root goal prematurely when that action is required only by an agent-chosen task, proof path, or fidelity rung. The current combination of "highest rung allowed", accepted pending tasks, and owner-only classification against an affected dependency chain can promote a safe path-local stop into a false owner blocker even when another real, goal-preserving boundary remains available.

## What Changes

- Classify owner-only blockers against the still-current original accepted outcome, not merely the current task, OpenSpec change, proof path, or dependency chain.
- Treat a protected prerequisite required only by an agent-chosen path as evidence to replan and reconcile proposal/design/spec/tasks autonomously, while preserving the protected action and narrowing claims to the replacement real boundary.
- Make authority a ceiling rather than a reason to climb the fidelity ladder; use the first safely reachable real boundary sufficient to observe the accepted effect, and move higher only when a current requirement, invariant, or unresolved equivalence risk requires it.
- Keep pending tasks required only while they remain consistent with the current user-bounded outcome, and keep a blocked live-attempt gate scoped to its exact path or lane.
- Extend the existing pre-escalation loaded-behavior proof with one stale-overbroad-path scenario that must replan without a user question, specialist call, protected-action execution, synthetic success, or end-to-end claim.
- Replace conflicting always-loaded wording and deterministic markers instead of appending another recovery framework, preserving the reviewed instruction-budget maxima.

## Outcome Capsule

- **Outcome:** Before an owner blocker is reported, main distinguishes a protected action necessary for the original accepted outcome from one necessary only for a chosen path. A path-only blocker causes autonomous artifact reconciliation and execution of an available safe real route; a true outcome blocker still produces the existing self-contained owner handoff.
- **Operating Envelope:** Always-loaded OpenCode main-session authority, Material qualification guidance, OpenSpec planning controls, and the existing disposable same-model pre-escalation proof runner. Evaluation uses synthetic local files and commands with no credential, machine, remote, destructive, deployment, installation, release, publication, or protected external effect.
- **Non-Goals:** Bypassing or assigning interlocks; simulating protected readiness; weakening credentials, authorization, safety, compatibility, restoration, cleanup, or live-attempt gates; accepting unit/mock/synthetic evidence as real-boundary proof; making pending tasks optional; giving `troubleshooter` production authority; giving the completion arbiter replan or protected-decision authority; or adding a new blocker skill, plugin, lifecycle stage, or generic semantic classifier.
- **Non-Deferrable Invariants:** Protected actions remain owner-controlled when required by the accepted outcome; replacement proof remains real and sufficient for the accepted effect; path replan cannot inflate claims to end-to-end or machine equivalence; user-bounded scope remains controlling; evidence and Live-Attempt Gates stay path-scoped; main remains the only correction, proof, validation, and lifecycle authority.
- **Observable Proof:** Through the actual loaded primary entry point, a scenario whose stale task requires a protected action but whose original goal and non-goals admit an unused disconnected real observation executes that route, emits no owner question or specialist consultation, performs no protected/bypass command or file mutation, and reports only the narrower path-scoped claim. Paired true-owner evidence still produces `OWNER_REQUIRED`. Deterministic contracts, strict validation, instruction inventory/budget, and replay are green for the same candidate.
- **Material Residual Risks:** Model adherence may remain version-sensitive; ambiguous or genuinely outcome-required observable proof must still fail closed; project-local artifacts can remain stale until main reconciles them; a narrower real boundary cannot prove behavior that depends on a higher rung.
- **Stop Line:** Stop only the affected path while a safe goal-preserving real route remains. Ask the owner only when evidence shows the original accepted outcome itself requires an exact protected action and no unused safe real substitute can advance it. Any candidate that bypasses a protected action, accepts synthetic success, weakens the accepted proof, or still asks in the stale-path scenario returns to `development`.

## Capabilities

None.
