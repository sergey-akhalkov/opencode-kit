## Context

See `proposal.md` for motivation and the bounded claim. The current main specification already requires plain, concise, accurate communication, while the loaded `Principle of Least Surprise` now states only a broad compactness rule. `global/AGENTS.md` and the maintained compaction prompt require `Live-Attempt Gate: clear | blocked | unknown` plus a governed path or lane, but they do not explicitly prevent a path classification from being applied to resource availability, authority, environment, or the accepted outcome.

The archived `clarify-user-communication-guidance` change previously placed stronger wording in `global/AGENTS.md` and verified one live response. Later instruction consolidation removed most of that operational wording while leaving the stronger main specification in place. The implementation must restore the missing semantic invariant without reintroducing a second communication framework or a long always-loaded checklist.

## Goals / Non-Goals

**Goals:**

- Put one compact universal status-scope rule in the existing canonical communication principle.
- Add only the Live-Attempt-specific operational delta at the existing gate owners and compaction source.
- Preserve mixed status facts through an actual installed main response and OpenCode compaction/reconstruction path.
- Retain the behavior with deterministic drift checks and a finite extension of the existing consumer-outcome proof mechanism.

**Non-Goals:**

- Add an on-demand wording skill, reviewer, Practice Owner, general prose linter, or mandatory response template.
- Reintroduce all communication text removed by prior instruction consolidation.
- Change live-attempt classification, replay, authorization, restoration, cleanup, or protected-boundary semantics.
- Claim correctness for unobserved models, languages, prompts, or consumer overrides.

## Decisions

### Extend the existing canonical principle

Replace or consolidate the current `Principle of Least Surprise` communication sentence so it requires each status to name its exact subject and evidence scope and keeps material adjacent dimensions separate. Keep the rule compact and general; do not add a second communication section or copy the dimension list into every skill and agent.

Alternative rejected: restore the full archived communication block in `global/AGENTS.md`. It would increase always-loaded duplication and still leave the canonical principle weaker than the specification.

### Keep Live-Attempt detail at current owners

Narrowly update the existing Live-Attempt output wording in `global/AGENTS.md`, `change-ready-sdlc`, and the canonical compaction prompt source. Require the governed invocation/path, gate classification, missing/failing evidence, and operational consequence to remain separate from resource, authority, environment, and outcome facts. Materialize maintained config mirrors through the existing installer/synchronization ownership rather than editing unrelated host or consumer sources.

Alternative rejected: define a universal structured status schema for every response. Most responses have one unambiguous subject, so mandatory fields would add noise and undermine concise communication.

### Validate exact facts, not prose quality

Extend the existing consumer-outcome regression harness with one `status-scope` finite decision pack. Each synthetic case supplies reviewed facts and expects stable structured fields for resource availability, authority, proof-path readiness, evidence state, operational consequence, and accepted outcome. Preserve the corresponding privacy-safe assistant text and reject direct contradictions, but do not score style, clarity, or semantic quality with a deterministic heuristic.

Use the installed OpenCode SDK `session.summarize` boundary for the compaction lane. Seed an isolated session with the reviewed mixed-status facts, invoke the actual configured compaction agent, then reconstruct the status fields from the compacted context in a fresh bounded turn. Baseline and candidate arms use identical prompts, fixtures, permissions, model routes, and environment identities. Provider-free replay reruns the complete evaluator without another model call.

Alternative rejected: add a new standalone wording runner. The existing consumer-outcome runner and shared OpenCode proof client already own matched source capture, environment identity, bounded configured calls, evidence preservation, and cleanup.

### Retain one bounded claim

CSA-001 is the only change-level claim owner. Deterministic validation checks its reviewed fields and evidence references; the behavior evaluator may support only the finite maintained population. Other models, languages, long-session contexts, and overrides remain explicit unresolved observations rather than inferred coverage.

## Proof Ladder And Failure Boundaries

- **Current Rung**: direct source/spec/history inspection plus the reproduced user report showing cross-layer ambiguity; no new candidate exists.
- **Next Real Boundary**: matched installed baseline/candidate main-response capture for the known-resource/path-unknown case, followed by actual SDK compaction and reconstruction in isolated synthetic sessions.
- **Authorization**: standing authorization permits the minimum bounded synthetic configured-provider calls required for kit instruction validation; no external effect, purchase, quota increase, consumer project, or hardware action is authorized.
- **Safeguards**: fixed non-sensitive fixtures, effect-denied permissions, finite call and byte bounds, one readable source candidate per arm, no source mutation by the proof session, and exact model/OpenCode/config identities.
- **Restoration And Cleanup**: delete proof-owned sessions and disposable roots, stop proof-owned processes, preserve immutable evidence, and treat unknown cleanup or liveness as terminal for the affected lane.
- **Evidence**: source and prompt digests, scenario facts, structured decisions, assistant text, compaction summary/context, reconstruction, tool/effect inventory, exits, stdout/stderr, cleanup, evaluator output, and maximum claim.

Failure boundaries:

- A source/mirror mismatch blocks candidate capture and names the stale path; it does not authorize editing a foreign config source.
- A configured capture failure preserves the raw bundle and receives provider-free terminal replay before any equivalent retry.
- A structured decision mismatch is candidate behavior evidence for only that scenario after runner, evaluator, and environment identity are qualified.
- A prose-only concern without an exact contradictory fact remains review evidence and is not converted into deterministic scoring.

## Risks / Trade-offs

- [The compact rule is too abstract] -> keep one exact Live-Attempt delta and the maintained mixed-status behavior cases.
- [The dimension list makes every response verbose] -> require separation only when states differ or omission could cause a false inference.
- [A model writes correct structured fields but ambiguous prose] -> preserve the text, reject exact contradictions, and use bounded human/read-only review for ambiguity without encoding a fuzzy score.
- [Compaction route differs from the main route] -> capture both routes with their actual configured model identities and limit CSA-001 to those observations.
- [Instruction consolidation removes the rule again] -> add deterministic canonical-owner and maintained-mirror markers plus the retained behavior pack.
- [Active worktree changes overlap proof tooling] -> do not mutate an overlapping owner; wait for closure or record an exact transfer before implementation.

## Migration Plan

1. Freeze baseline source, prompt, scenario, model, environment, and current active-source identities before changing loaded instructions.
2. Add the finite pack and evaluator expectations first, then capture the frozen baseline without modifying its source.
3. Apply the smallest canonical principle and Live-Attempt/compaction source edits, materialize maintained mirrors, and run deterministic checks.
4. Capture the readable candidate through installed main-response and compaction/reconstruction paths, then replay both arms provider-free to the terminal CSA-001 verdict.
5. Run applicable project validation and document the bounded maximum claim and unresolved observations.
6. Activate only through a new OpenCode session or supported reload after proof; do not change consumer projects or external systems.

Rollback restores the reviewed pre-change instruction and compaction source bytes through normal version control, rematerializes kit-owned mirrors, reruns deterministic validation, and starts a new OpenCode session. Evidence artifacts remain immutable and are not rewritten during rollback.
