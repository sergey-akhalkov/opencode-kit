# Strategy History

## 2026-08-23 - Keep all practice responsibility in main

- **Objective**: Reduce coordination cost while preserving one role with complete outcome context.
- **Approach**: Keep main as both Outcome Owner and semantic owner of every working practice, adding only more concise global guidance and optional reviewers.
- **Evidence**: The current runtime already follows this shape. Inventory found nineteen agents and detailed routing, but no agent is registered as a Practice Owner; the active user explicitly separated main's result responsibility from specialized subagent practice responsibility.
- **Outcome**: Rejected for this change.
- **Reason**: It preserves the exact cognitive and maintenance concentration the accepted outcome is intended to remove.
- **Do Not Repeat Until**: The user changes the responsibility model or runtime evidence shows explicit practice ownership cannot preserve outcomes and safety under any bounded trigger design.
- **Evidence-Based Retry Condition**: Matched owner-routing scenarios reproduce a material regression uniquely caused by separating practice responsibility and no narrower taxonomy, trigger, report, or kernel correction can resolve it.

## 2026-08-23 - One agent per rule with all-owner fan-out

- **Objective**: Guarantee that no individual rule is missed.
- **Approach**: Create a subagent for every principle or operational bullet and ask all agents to declare applicability for every task.
- **Evidence**: The maintained philosophy and operational authority contain many coupled rules, while current agents already overlap on protocol/wire/concurrency, readiness/deployment, testing/domain, and architecture/reduction concerns. Loader inventory shows bodies are on demand, but every model call and returned report still adds latency, context, and reconciliation work.
- **Outcome**: Rejected.
- **Reason**: It replaces main's policy burden with agent explosion, noisy applicability votes, and a larger integration burden.
- **Do Not Repeat Until**: Exact rule-level isolation is required by a concrete independent authority or safety boundary that cannot share one coherent practice owner.
- **Evidence-Based Retry Condition**: A maintained scenario proves a material rule is repeatedly missed because its current practice family is intrinsically ambiguous, and splitting only that family reduces total routing and context cost.

## 2026-08-23 - Central practice router or mega-owner

- **Objective**: Hide the complete practice taxonomy from main behind one specialist call.
- **Approach**: Add an always-invoked routing agent or one subagent that knows and adjudicates every practice before other work begins.
- **Evidence**: Such an agent would need the same broad policy context as main, would add a model call to zero-trigger Ordinary Small tasks, and would either become a second orchestrator or still require main to reconstruct every referral. Current agent descriptions already provide cheap discovery metadata.
- **Outcome**: Rejected.
- **Reason**: It moves rather than removes the bottleneck and creates a new single point of semantic failure.
- **Do Not Repeat Until**: Runtime evidence shows that compact discovered triggers cannot route maintained practices with bounded main effort.
- **Evidence-Based Retry Condition**: Matched scenarios reproduce repeated wrong-owner selection after trigger/description/registry corrections, and one bounded router demonstrably lowers calls and context without taking authority or weakening zero-trigger behavior.

## 2026-08-23 - Let Practice Owners edit and approve their own artifacts

- **Objective**: Make each owner independently maintain its complete practice.
- **Approach**: Give owner agents write access to their canonical rules, skills, registry rows, and agent bodies and accept their self-review as maintenance closure.
- **Evidence**: Current leaf reviewers intentionally deny mutation and nested orchestration. Path-scoped self-editing would still combine diagnosis, policy authoring, and approval in one model context, create concurrent writer/liveness obligations, and provide no independent evidence when the owner's own trigger changes.
- **Outcome**: Rejected.
- **Reason**: Semantic ownership does not justify mutation authority or self-certification; main must retain integration and an owner-under-change needs prior or independent evidence.
- **Do Not Repeat Until**: A technically enforced isolated writer model and independent post-write review can show lower total risk and cost than main-owned edits.
- **Evidence-Based Retry Condition**: Repeated maintenance evidence shows main-owned authoring is the actual bottleneck, a bounded owner write scope has deterministic rollback and terminal liveness, and independent review remains separate.

- **Approach**: Register fifteen coherent practice families, adapt and narrow fourteen existing specialists, add one read-only execution-safety owner, keep detailed bodies on demand, and route through compact discovery descriptions plus a reviewed registry.
- **Evidence**: Current agent contracts already align closely with fourteen families; loader inventory separates only 2,350 token proxy of discovery metadata from 69,810 of on-demand bodies; no current agent coherently owns protected execution/worktree/writer-liveness practice. The approach preserves main as sole orchestrator and requires no scheduler, dependency, rename, or owner write authority.
- **Outcome**: Selected for proposal, specs, design, and tasks.
- **Reason**: It directly implements the accepted responsibility split while minimizing new concepts, calls, catalog growth, and always-loaded text.
- **Do Not Repeat Until**: N/A - selected strategy.
- **Evidence-Based Retry Condition**: Provider-free preflight or matched baseline/candidate proof shows the fifteen-family registry, one new owner, or trigger-based routing cannot preserve outcome, authority, safety, context budgets, and zero-trigger behavior; then revise only the disproven boundary and preserve narrower green evidence.
