## Why

The kit has a mature working philosophy, operational rules, skills, and nineteen specialized subagents, but the catalog does not assign any subagent explicit semantic ownership of a maintained practice. Main therefore remains responsible both for the user outcome and for remembering, applying, and maintaining every detailed practice, while overlapping reviewers can inspect the same concern without one accountable practice boundary.

## Outcome Capsule

- **Outcome**: Every maintained semantic practice in the selected OpenCode runtime surface has exactly one discoverable specialized Practice Owner subagent that controls the practice at material runtime triggers and reviews maintenance changes to its owned rule set, while main remains solely responsible for the user outcome, scope, integration, Runtime Proof, finding disposition, and final handoff.
- **Operating Envelope**: Repository-managed global principles, `AGENTS.md`, skills, subagents, runtime-surface profiles, deterministic validators, and bounded same-model synthetic OpenCode workflows for the current `core` and `all` surfaces. Practice Owners remain leaf or existing bounded specialist roles; no owner receives autonomous orchestration, product mutation, lifecycle, or protected-action authority.
- **Non-Goals**: One agent per bullet; an all-owner fan-out on every task; a central routing agent; autonomous owner-to-owner dispatch; transferring product, scope, architecture-decision, claim, stage, release, or protected-action authority from main or the user; allowing owners to edit or self-approve their instruction artifacts; replacing skills, deterministic validators, SDET, implementation workers, the completion guard, or domain execution workflows; installing or activating the candidate runtime.
- **Non-Deferrable Invariants**: Main remains the sole outcome owner and orchestrator. Every maintained practice and normative rule anchor has one primary Practice Owner, and every owner has one coherent primary practice. Compact safety, authorization, worktree, evidence-not-authority, owner-boundary, and proof-floor invariants remain loaded before any dispatch. Practice Owner evidence never authorizes mutation or acceptance. Ordinary Small work with no registered material trigger launches no owner. A matched trigger receives one bounded owner consultation; unavailable or inconclusive ownership remains explicit and never becomes a silent pass. Semantic registry data is reviewed input outside helper code; validators derive only structural facts. Practice changes cannot be certified solely by the changed owner itself.
- **Observable Proof**: Validate one stable practice registry, exact owner/agent/profile/catalog bindings, unique ownership, trigger and maintenance contracts, least-privilege permissions, and loader-visible budgets. Through the actual installed OpenCode entry point in fresh disposable repositories, compare the unchanged baseline and candidate for a trivial no-owner task, a single-practice trigger, disjoint multi-practice triggers, an overlap boundary, a protected-action case, an unavailable-owner case, and a practice-maintenance change. Observe no all-owner fan-out, the exact intended owner reports a bounded practice observation, main dispositions every finding without surrendering outcome authority, forbidden effects remain absent, and cleanup is complete.
- **Material Residual Risks**: A poor practice taxonomy can move rather than remove cognitive load; owner calls add latency and report context; model-sensitive routing can miss or over-trigger a practice; existing reviewer checks overlap; selected profiles may omit an owner; an owner can drift from its skill or canonical rules; and active instruction changes currently share affected sources. Synthetic workflows cannot prove optimal routing for every repository, language, model, or future practice.
- **Stop Line**: Finish when the versioned ownership model, initial complete practice roster, owner contracts, one missing execution-safety owner, narrowed existing owner boundaries, trigger-based main routing, profile composition, maintenance/self-change safeguards, deterministic validation, matched runtime evidence, active-change reconciliation, README/spec synchronization, and project-native validation are complete. Do not add an agent scheduler, owner hierarchy, agent self-editing, mandatory ordinary-work review, general workflow engine, profile auto-selection by model inference, or unrelated instruction cleanup.

## Claim And Evidence Scope

- **Claim ID**: `POA-001`
- **Claim Class**: Loaded instruction and subagent-routing behavior for explicit practice ownership.
- **Population**: The maintained synthetic scenario set covering trivial no-trigger work, one core-practice trigger, independent multi-practice triggers, a documented owner-boundary overlap, protected-action handling, unavailable-owner handling, and maintenance of an owned instruction practice.
- **Coverage Basis**: Deterministic registry/profile/permission/catalog validation plus matched baseline/candidate OpenCode workflows for every maintained scenario under the same model, variant, permissions, prompts, fixtures, and environment.
- **Production Path**: The resolved `core` and `all` global runtime surfaces, discovered agent descriptions, always-loaded routing, and main-owned task/dispatch path.
- **Comparison Paths**: The frozen unchanged runtime source and the candidate practice-ownership source exercised in isolated disposable config, data, cache, session, and repository roots.
- **Environment**: The same OpenCode build, effective model and variant, operating-system class, dependency identities, selected profile, permissions, synthetic repositories, and non-sensitive prompts in both arms.
- **Real Oracle**: Exact child-agent identity and role, practice applicability and observation fields, main disposition, task outcome, tool/effect boundaries, validation output, loader-visible inventory, and terminal cleanup rather than prose claims or agent counts.
- **Unresolved Observations**: Unrepresented repositories, languages, models, domain combinations, installed third-party overrides, and future practices remain unqualified.
- **Maximum Claim**: The candidate gives every practice in the reviewed initial roster one structurally valid, loader-visible owner and improves or preserves routing, authority, safety, outcome, and friction oracles for the maintained scenario population. It does not prove universal practice coverage, optimal agent granularity, or lower latency in untested workflows.

## What Changes

- Add a first-class `library-practice-ownership` capability with a versioned reviewed registry that maps each maintained practice to one owner agent, canonical rule surfaces, runtime profile, material trigger, maintenance boundary, and non-authority contract.
- Reclassify the current flat agent catalog into Practice Owners, execution roles, optional cross-cutting reviewers, and control-plane agents. Reuse and narrow existing specialists wherever their current domain fits; add only the missing execution-safety Practice Owner in this increment.
- Give Practice Owners explicit runtime and maintenance review modes with compact practice-level observations. Main must disposition every reported finding or unknown but remains the only result, integration, correction, and owner-handoff authority.
- **BREAKING**: Replace the rule that every read-only reviewer is purely optional with trigger-required Practice Owner consultation for only the registry's named material conditions. The consultation is not an acceptance or lifecycle gate, and zero-trigger Ordinary Small work remains owner-call-free.
- Keep practice descriptions in on-demand owner bodies and discovery metadata. Add only a compact generic owner-routing contract to always-loaded authority, with no central routing agent or per-practice policy copy.
- Bind installed practice artifacts and their owners atomically in runtime-surface profiles. Core retains its enforced startup/discovery ceilings; domain owners remain profile-scoped unless their practice is selected.
- **BREAKING**: Add the three missing core Practice Owners and move the optional non-owner `final-candidate-reviewer` from `core` to `all`, preserving its explicit optional route while paying for owner discovery inside the existing core budget.
- Add deterministic ownership, profile, catalog, permission, and drift validation from reviewed semantic seed data, while proving routing effectiveness through bounded same-model baseline/candidate workflows.
- Reconcile `improve-change-locality-guidance` so main owns the concrete architecture/result decision while the specialized owner owns the change-locality practice, preserving pay-as-you-go design and the no-mandatory-ordinary-review negative control. Serialize later instruction mutation behind the current `enforce-claim-evidence-closure` owner and other overlapping active changes.

## Capabilities

### New Capabilities

- `library-practice-ownership`: Defines practice identity, exclusive semantic ownership, runtime and maintenance modes, main/owner authority separation, trigger routing, overlap handling, profile availability, and evidence requirements.

### Modified Capabilities

- `library-instruction-artifacts`: Adds the Practice Owner artifact contract, reviewed ownership registry, self-change independence, catalog synchronization, structural validation, and context-efficient behavior proof.
- `library-change-ready-sdlc`: Distinguishes main's outcome accountability from triggered Practice Owner responsibility without weakening protected boundaries, Runtime Proof, optional-review proportionality, or main disposition.
- `library-runtime-surface-profiles`: Requires every selected maintained practice to include its exact owner agent and keeps owner discovery within the enforced profile budgets.

## Impact

- Primary instruction surfaces: `global/principles-of-work.md`, `global/AGENTS.md`, the shared agent contracts under `instructions/`, selected `global/agents/*.md`, and their paired skills or operational adapters.
- Runtime catalog: the existing nineteen agents are classified and narrowed; one read-only execution-safety owner is added; no owner can dispatch another agent or mutate production/instruction sources.
- Deterministic source: one reviewed practice-ownership seed, schema/validator/contracts, profile and README synchronization checks, and focused fixtures/tests.
- Behavior evidence: extend the existing disposable OpenCode proof conventions with scenario-specific practice-routing capture, replay, evaluation, source/model identity, bounded reports, and cleanup; do not create a generic agent scheduler or fuzzy architecture scorer.
- Active-change coordination: no shared instruction/runtime mutation begins until current write ownership is terminal or explicitly transferred. Existing claim-evidence, completion, roadmap, and workstation evidence remains intact.
- Public product APIs, persisted product data, provider configuration, credentials, remote systems, deployment, release, installation, and active workstation state are unchanged by this planning increment.
