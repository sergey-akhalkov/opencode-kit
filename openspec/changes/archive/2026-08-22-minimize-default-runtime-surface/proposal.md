## Why

The installed default exposes every domain skill and agent plus about 13.3k startup token-proxy to every project, while personal host authorization and permissive tool policy are committed beside portable authority. This makes unrelated work pay context/routing cost and makes the reusable source owner-specific before measured consumer benefit exists.

## Outcome Capsule

- **Outcome**: A new installation loads one portable core runtime surface with no personal facts, no unrelated domain packs, precise discovery metadata, and a smaller measured context while preserving required quality/safety oracles in the consumer outcome gate.
- **Operating Envelope**: New/disposable installs and staged global sources; `core` is the default profile, `all` remains an explicit compatibility profile; existing machine-local config is never overwritten; provider calls occur only through the separately governed consumer outcome proof.
- **Non-Goals**: Removing domain artifacts, changing their domain behavior, migrating an existing machine automatically, changing current model routing, reducing safety authority without matched evidence, or fixing OpenSpec/runtime/Windows findings owned by other changes.
- **Non-Deferrable Invariants**: Portable authority remains complete; protected boundaries and real-proof requirements cannot weaken; personal authorization remains available only through an official gitignored source; a restricted default cannot silently become permissive; optional packs cannot become loader-visible until selected.
- **Observable Proof**: A fresh staged install reports only core discovery/runtime sources, contains no maintainer identity, uses ask-level mutation permission until explicit machine-local autonomy opt-in, stays within 12,000 startup and 1,200 discovery token-proxy, and passes no-regression consumer scenarios; explicit `all` preserves the full catalog and its disclosed permissive compatibility policy.
- **Material Residual Risks**: A smaller catalog may miss a domain trigger; OpenCode loader changes can alter visibility; exact token proxies do not prove behavior; existing installations remain broad until explicitly re-provisioned.
- **Stop Line**: Finish core/all profile selection, portable/machine-local authority separation, description precision, budget/loader validation, fresh-install proof, and matched no-regression evidence. Do not optimize domain bodies or migrate existing users.

## What Changes

- Add a maintained runtime-surface profile contract with `core` default and explicit `all` compatibility selection.
- Move personal standing authorization and permissive main-tool opt-in out of committed portable instructions/config and into documented gitignored machine-local sources.
- Narrow skill discovery descriptions to literal domain triggers and explicit stay-quiet boundaries.
- Replace grandfathered default context ceilings with smaller core ceilings while retaining separate full-catalog reporting.
- Require staged loader-visible inventory and consumer no-regression evidence before retaining reductions.

## Capabilities

### New Capabilities

- `library-runtime-surface-profiles`: Defines default core and explicit optional runtime surfaces, loader visibility, profile selection, budgets, and compatibility behavior.

### Modified Capabilities

- `library-instruction-artifacts`: Requires precise discovery descriptions and evidence-backed portable-authority reduction.
- `library-config-portability`: Changes new-install defaults to owner-neutral ask-level permissions with explicit machine-local autonomy opt-in, without rewriting existing local config.

## Impact

- Profile manifests, global install/provisioning, runtime source inventory, instruction budget, skill validators, README/getting-started guidance, portable config/instructions, and consumer outcome proof inputs.
- Security-sensitive default behavior for new installs; no automatic host mutation or migration in this change.

## Implementation Dependencies

- Planning-only until `reduce-workflow-ceremony` restores strict validity and releases `global/AGENTS.md` plus overlapping instruction/config requirements.
- Core retention requires a completed baseline/current gate from `establish-consumer-outcome-regression-gate`, including generated profile identities in its governed manifest.
- Shared installer/Windows command files serialize after the disjoint resolver/MCP portion of `harden-cross-platform-bootstrap-validation`; ownership enforcement from `reconcile-openspec-ownership-and-evidence` must be active before default migration.
