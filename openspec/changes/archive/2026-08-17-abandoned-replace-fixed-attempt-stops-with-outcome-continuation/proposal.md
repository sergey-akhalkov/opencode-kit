## Why

An agent can still convert a one-shot live invocation safeguard into a permanent
mission stop, close every OpenSpec task while the accepted outcome remains unmet,
and ask the owner to approve its own process controls. The reproduced P1S1 case
made this concrete: a failed packet-observer canary and stale component binding
were diagnosed, direct startup facts remained trustworthy, yet `zero retries`, a
terminal handoff, and `23/23` task status temporarily displaced the still-unmet
receipt goal and the next safe correction.

## Outcome Capsule

- **Outcome:** Loaded OpenCode and OpenSpec workflows continue an unfinished
  accepted outcome through every causally justified, authorized, safe successor
  without a fixed mission-wide attempt ceiling or routine owner question. One-shot
  execution identities remain non-reusable, but failed attempts, checked tasks,
  and process stop lines cannot complete or abandon the root goal. OpenSpec
  reflection becomes optional evidence outside the product task graph rather than
  a mandatory final implementation stage.
- **Operating Envelope:** Kit-owned global instructions, Change-Ready guidance,
  OpenSpec propose/apply/archive skills and commands, task/completion semantics,
  completion-guard arbitration, portable operation-gate resolution, maintained
  validators and same-model disposable workflow evaluations. External, physical,
  credentialed, destructive, remote, deployment, release, and owner-controlled
  cost boundaries remain separately authorized and fail closed.
- **Non-Goals:** Unlimited unchanged retries, automatic reuse of an authorization
  or output root, bypassing live-attempt replay, safety, identity, liveness,
  restoration, or cleanup gates, weakening explicit user task limits, inferring
  success from partial evidence, changing OpenSpec CLI status semantics upstream,
  or modifying the PMAC target repository as part of this kit change.
- **Non-Deferrable Invariants:** Each execution attempt is finite; unchanged
  mechanisms stop on stagnation; a repeated live/high-cost action requires a
  causal delta, preserved-corpus replay, current authority, known state, and exact
  cleanup; checked tasks never substitute for observable outcome proof; owner-only
  status still requires one exact protected action with no safe goal-preserving
  route; historical evidence remains immutable.
- **Observable Proof:** Through the actual installed global source and same selected
  model/profile, compare baseline and candidate on the reproduced case containing
  `23/23`, `Development-Stage: development`, no receipt, `zero retries`, direct
  startup success, a zero packet observer and failed positive control, stale
  component/leg binding, an already authorized corrected route, and a deliberately
  ambiguous operation-gate source placeholder. The candidate preserves the failed
  attempt, reopens/adds outcome work, resolves the active global helper, performs
  the safe local/no-effect correction path, asks no process question, and stops
  only at an actual unresolved protected boundary. Controls cover unchanged live
  repetition, true owner-only action, explicit user pause, and an achieved outcome.
- **Material Residual Risks:** Model reasoning can still misclassify whether a
  mechanism is causally distinct or an outcome is achieved; looser mission-level
  counting can expose a latent retry loop if stagnation and completion arbitration
  regress; removing mandatory retrospectives can reduce captured improvement ideas;
  synthetic cases cannot represent every physical workflow.
- **Stop Line:** Finish when canonical and proportional instruction surfaces use
  evidence-gated mission continuation, OpenSpec completion and archive routing
  reject checked-but-unmet outcomes, future proposals no longer add mandatory
  final-history tasks, active global-source resolution is deterministic, exact
  baseline/candidate and negative-control workflows pass through installed routes,
  and project-native validation is green. Do not authorize or run a target-project
  live action, introduce a new workflow engine, or retain both old and new retry
  semantics as layered overrides.

## What Changes

- Replace permanent or fixed mission-wide attempt stops with evidence-gated
  continuation: no unchanged automatic replay, but no arbitrary cap on causally
  distinct successors while the accepted outcome remains unfinished.
- Define separate vocabulary and behavior for a finalized invocation, an unfinished
  accepted outcome, and a completed or explicitly abandoned change.
- Require apply, archive, and completion arbitration to reconcile task status with
  current outcome proof; checked tasks plus `development` or a missing required
  receipt must reopen or add work rather than produce completion.
- Remove the mandatory creation-time final-history-retrospective task and its
  automatic Session-Derived Improvement expansion from future changes. Retain
  bounded strategy history only where it records decision-changing attempts, and
  keep optional feedback outside accepted product scope.
- Resolve `<global-source>` deterministically from the active loader-visible source,
  preferring `OPENCODE_CONFIG_DIR` when set, and fail with actionable evidence only
  after supported source resolution is exhausted.
- Replace static phrase-only confidence with installed same-model regression
  scenarios derived from the P1S1 failure, while preserving true owner, user-pause,
  safety, and unchanged-strategy controls.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `library-change-ready-sdlc`: Replace fixed mission attempt ceilings and permanent
  SDET/root stop wording with causal, evidence-gated continuation that preserves
  finite invocations and protected-action gates.
- `library-instruction-artifacts`: Make outcome dominance and invocation-versus-
  mission semantics concise loaded authority, remove mandatory final-history task
  generation, and require transcript-derived installed behavior evaluation.
- `library-spec-workflow-integrity`: Reconcile OpenSpec task completion with accepted
  outcome proof, route checked-but-unmet changes back to apply, simplify reflection,
  and resolve portable operation helpers from the active global source.
- `session-completion-guard`: Reject `allow_stop` and process-only owner escalation
  when an unfinished requirement has a safe causally distinct continuation, even
  if tasks are checked or an agent-authored attempt count is exhausted.
- `library-config-portability`: Define deterministic active global-source resolution
  for portable workflow helpers under `OPENCODE_CONFIG_DIR` and supported fallback
  inspection.

## Impact

- Loaded policy and workflow sources under `global/AGENTS.md`,
  `global/skills/change-ready-sdlc/`, OpenSpec propose/apply/archive skills and
  commands, and `global/agents/session-completion-arbiter.md`.
- Normative OpenSpec specs, project templates/mirrors, deterministic validators,
  instruction contracts, and focused tests that currently require permanent-stop,
  immediate-block, or final-history markers.
- Existing pre-escalation/completion-guard proof tooling and one maintained
  transcript-derived baseline/candidate evaluator; no target product repository,
  public API, dependency, credential, deployment, installation, or remote state is
  changed.
