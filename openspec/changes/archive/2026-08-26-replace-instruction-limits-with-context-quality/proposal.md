## Why

The kit's fixed instruction token-proxy ceilings were inherited from earlier snapshots rather than derived from a demonstrated context, quality, or model boundary. They now pressure maintainers to shorten unique safety, routing, and proof contracts to satisfy numbers, while the more relevant risks are duplicated authority, contradictory instructions, unnecessary prose, and behavior regressions.

## What Changes

- **BREAKING** Remove strict startup, discovery, on-demand-body, and catalog token-proxy maxima from canonical requirements and repository validation. Retain loader-visible startup, discovery, and on-demand measurements as separate diagnostics, never as one claimed prompt size or a pass/fail quality proxy.
- Replace budget compliance with context-quality governance: every maintained instruction has one canonical owner or an explicit loader-boundary reason for repetition; exact repeated operative instruction blocks inside or across maintained model-facing files fail deterministic validation; near-duplicates and possible contradictions are reported for review rather than changed by heuristic code.
- Add an idempotent instruction canonicalization practice for Markdown prose. A checked-in, reviewed rule set may automatically apply only mechanical, meaning-preserving transformations outside protected spans; a second pass must produce zero diff. Semantic shortening, synonym selection, contradiction resolution, and cross-file deletion remain review-only and require affected consumer no-regression proof.
- Extend the existing instruction inventory instead of adding a competing context scanner. Report source scope, canonical-owner/exception identity, duplicate locations, rule IDs, before/after measurements, unknown sources, and deterministic ordering without emitting private instruction bodies from loader-visible sources.
- Reconcile active change plans that currently require unchanged ceilings or budget payment so they instead preserve unique contracts, remove only evidenced duplication, inspect context diagnostics, and pass relevant routing/consumer behavior checks.
- Remove the checked-in budget seed and its fail-closed materialization/proof contract after replacement diagnostics and quality checks are proven through the maintained CLI and strict validation paths.

## Outcome Capsule

- **Outcome:** Maintainers can add or improve unique instructions without an arbitrary numeric rejection, while deterministic checks prevent exact duplicate normative authority and a safe fixed-point canonicalizer removes mechanical text waste without silently changing meaning.
- **Operating Envelope:** Maintained model-facing Markdown bodies enumerated by the updated inventory under global/root/project instructions, agents, skills, commands, templates, and OpenSpec artifact instruction/rule/template sources; profiles participate only in loader identity and separate measurements, while ordinary documentation, canonical product specs, active plans, archives, and evidence are outside duplicate enforcement; local check/report/fix operations; disposable fixtures and fresh loader/consumer evaluation; no active global installation or external mutation.
- **Non-Goals:** Automatic semantic equivalence, model-authored paraphrasing, fuzzy quality scores, target compression percentages, token-count optimization, automatic near-duplicate merging, archive/evidence rewriting, private loader-visible text disclosure, or proving that every differently worded instruction is unique or contradiction-free.
- **Non-Deferrable Invariants:** Unique safety, authority, routing, proof, diagnostics, worktree, and live-attempt contracts remain intact; automatic fixes do not alter normative modals, negation, conditions, exceptions, commands, paths, identifiers, URLs, numbers, code, or quoted requirements; startup/discovery/on-demand measurements remain separate; deterministic findings never claim semantic proof; strict validation never mutates source; intentional repetition across independent loader scopes requires an explicit reviewed exception rather than silent suppression.
- **Observable Proof:** The maintained CLI reports separate context measurements without maxima; exact intra-file and inter-file operative instruction duplicate fixtures fail with both locations and canonical-owner guidance; intentional scoped repetition passes only with a reviewed exception; protected and semantic-near-duplicate fixtures are not auto-edited; canonicalization reaches a byte-identical second pass; malformed/cyclic rules fail closed; strict validation, fresh loader readback, and matched consumer scenarios preserve required behavior after the budget gate is removed.
- **Material Residual Risks:** Differently worded semantic duplication and contradiction still require human/model judgment; an exact duplicate can be operationally necessary when artifacts load independently; parser upgrades can change fix ranges; context can still become too large for a specific provider even when quality checks pass, so runtime inventory must expose measurements and unknowns honestly without converting one provider observation into a universal ceiling.
- **Stop Line:** Replace the two canonical ceiling contracts, budget seed/gate/proof, affected validation and documentation, and stale active-change controls; extend deterministic inventory/duplicate checks; add one reviewed fixed-point canonicalizer and focused fixtures; prove loaded no-regression. Do not add a semantic compressor, generic prose-scoring framework, provider-specific hard cap, background service, new reviewer, or automatic cross-file semantic deletion.

### Claim And Evidence Scope

Exact claim: for the explicit maintained model-facing Markdown category set enumerated by the updated inventory, deterministic fixtures and source readback prove separate context diagnostics, exact operative-block duplicate handling, protected-span preservation, and a zero-diff second canonicalization pass; matched fresh-loader consumer checks bound only the exercised routing/safety no-regression scenarios and do not claim general semantic equivalence.

- **Automation Dividend**: required - extend the existing instruction inventory with a stable duplicate-owner report and add one fixed-point Markdown canonicalizer runner whose reviewed rules, protected fixtures, and second-pass check replace repeated manual cleanup and arbitrary budget rematerialization.

## Capabilities

### New Capabilities

None. Context-quality governance extends the existing instruction-artifact and runtime-surface owners.

### Modified Capabilities

- `library-instruction-artifacts`: Replace enforceable numeric budgets with diagnostic context measurements, canonical ownership and exact-duplicate validation, and a deterministic fixed-point canonicalization contract.
- `library-runtime-surface-profiles`: Remove numeric core ceilings while retaining separate loader-visible measurements, required-owner completeness, explicit profiles, and behavior-based no-regression gates.

## Impact

- Canonical specs and active changes that currently require `13,279`, `12,000`, `1,200`, or checked-in reviewed maxima.
- `config/instruction-budget.json`, `tools/instruction-budget.ts`, the instruction-budget proof runner, strict library validation, focused tests, proof inventory, package scripts, and context-management documentation.
- `tools/instruction-artifacts-inventory.ts`, one shared context-quality parser/evaluator seam consumed by inventory, validation, and canonicalization, and their maintained output contracts.
- One development-only `textlint` dependency (current researched release `15.8.0`, compatible with the repository's Node `>=24` engine) as the selected Markdown/TxtAST fixer engine; repository-owned rules and fixtures retain semantic and upgrade ownership.
- No product API, persisted-data migration, remote system, deployment, installation, activation, or release behavior.
