## Why

Long-running and multi-domain work currently asks the main session to retain the user outcome, implementation state, safety and evidence obligations, every specialist trigger, and the detailed work itself. Recent maintained routing evidence already shows both missed material owner launches and overlapping launches, so adding more main-session checklists would increase the same cognitive load instead of reliably shifting expertise selection left.

This change introduces one bounded fresh team-advice path that helps main form the smallest sufficient task-specific team before substantial non-trivial work. Main remains the sole orchestrator and result owner; trivial owner-local work remains direct and gains no advisory ceremony.

## Outcome Capsule

- **Outcome:** For every new non-trivial root task, main obtains one fresh bounded recommendation that maps the current mission outcome and evidence to the smallest sufficient combination of direct main work, skills, and available subagents, including useful timing and dispatch-ready brief boundaries. An obviously trivial owner-local task proceeds directly. Main's primary function is successful mission orchestration: it retains goal and scope control, specialist selection, dispatch, dependency and integration control, Runtime Proof, finding disposition, protected decisions, and final handoff. Manual implementation remains an available tactic when it is the shortest trustworthy route, not main's default objective.
- **Operating Envelope:** Parentless user-facing OpenCode root mission episodes; repository-managed instructions, agents, skills, active runtime-surface profiles, deterministic catalogs, compaction continuity, and bounded same-model disposable workflows. Child specialists, completion guards, campaign executors, and unchanged propose/apply continuations do not create new advisory episodes. The advisor is read-only, receives privacy-safe task/evidence context, fetches the parent root's active available-artifact catalog through one read-only tool, launches no child, writes no product or instruction source, and performs no external or protected effect.
- **Non-Goals:** Guaranteed discovery of every theoretically relevant expert; calling every agent; a fixed reviewer or lifecycle sequence; a passive main that merely forwards reports; a second orchestrator; nested agent dispatch; automatic plugin interception of every turn; semantic routing by keyword/path score; launch-count KPIs; replacing exact Practice Owner triggers; replacing main's integration or evidence judgment; changing product, public API, persisted-data, security, deployment, or remote-state semantics.
- **Non-Deferrable Invariants:** Main remains the only root orchestrator and outcome/authority/integration/evidence owner. It maintains the mission spine, verifies specialist evidence and integrated behavior at the nearest sufficient real boundaries, and never accepts reports blindly; it also does not repeat bounded specialist work solely to create an illusion of control. The advisor may recommend but never dispatch, authorize, mutate, approve, complete, or expand scope. It optimizes for the smallest sufficient team and may return `main alone`. Recommendations name only active available artifacts, distinguish skills from fresh-context agents, state the earliest useful evidence boundary, and include an invalidation or reconsultation condition. Existing Practice Owner, SDET, writer-liveness, worktree, protected-boundary, Runtime Proof, and evidence-not-authority rules remain in force.
- **Observable Proof:** Through the actual installed OpenCode root entry point, matched baseline/candidate scenarios cover trivial direct work, non-trivial single-domain work, multi-domain work, skill-versus-agent routing, conditional later expertise, isolated production delegation with main-owned integration/proof, a material mid-task topology change, unavailable profile artifacts, and an overstaffing negative control. The retained candidate calls no advisor for the trivial scenario, calls one advisor before substantial non-trivial mutation in every maintained positive scenario, returns only available artifacts and task-specific timing/briefs, permits `main alone`, causes no nested dispatch or protected effect, and improves the maintained missed/extra-routing oracles without regressing outcome, safety, cleanup, context quality, or diagnostic visibility.
- **Material Residual Risks:** A model-sensitive advisor can still omit or over-recommend expertise; a default call adds latency and context; stale or incomplete runtime catalogs can misroute work; main can incorrectly disposition advice; a broad advisor role can become a new bottleneck or duplicate readiness/Practice Owner semantics; active changes currently touch readiness, campaign orchestration, complexity management, profiles, and shared instruction sources. Evidence will support only the maintained scenario population and exact source/model/environment, not universal routing correctness.
- **Stop Line:** Finish when one cohesive advisory behavior, one compact main routing rule, active-catalog input, smallest-team output contract, compaction continuity, profile/catalog bindings, matched behavioral proof, and focused structural validation are green. Do not add nested orchestration, a mandatory all-agent checklist, a persistent workflow database, automatic per-turn router plugin, semantic scoring helper, broad agent-roster redesign, generic organization framework, or unrelated reviewer/process changes.

## What Changes

- Add task-specific specialist team advising as a bounded control-plane capability for new non-trivial root tasks, with a direct trivial-work exemption.
- Provide the advisor with the actual active agent/skill catalog rather than a duplicated static roster.
- Require a smallest-sufficient-team engagement map that distinguishes direct main work, skills, immediate subagents, conditional subagents, dependencies, expected evidence, dispatch brief boundaries, and reconsultation conditions.
- Preserve main as the sole dispatcher and result owner while shifting detailed team-composition analysis to a fresh context.
- Make mission success, dependency control, integration, and evidence closure main's primary function; treat direct implementation as one dynamically selected resource rather than the default measure of control for non-trivial work.
- Replace the current absolute prohibition on a central routing agent with a narrower prohibition on routing authority, nested dispatch, mutation, and lifecycle control.
- Preserve current Practice Owner triggers as exact mandatory boundaries; advisory recommendations complement but do not replace them.
- Preserve current engagement-map state across compaction without injecting the full artifact catalog or creating a new completion stage.
- Add one dedicated `specialist-team-advisor` because team topology and mid-task engagement routing are distinct from the registered `outcome-readiness` practice; do not add a parallel routing skill or readiness-reviewer mode.
