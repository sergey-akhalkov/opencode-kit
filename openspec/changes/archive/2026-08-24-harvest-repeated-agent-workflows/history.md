## 2026-08-23 - Require one new script from every completed change

- **Objective**: Force continuous automation so repeated agent work is converted into fewer future tool calls.
- **Approach**: Make every OpenSpec change create at least one new script before complete archive, regardless of change profile or observed recurrence.
- **Evidence**: The owner reported recurring manual pipelines across sessions, especially repeated Git status/diff/history inspection. Current kit guidance already favors deterministic helpers, but `library-instruction-artifacts` and the archived `reduce-workflow-ceremony` evidence explicitly protect Ordinary Small completion from mandatory process work.
- **Outcome**: Rejected and narrowed before artifact authoring.
- **Reason**: A per-change new-file quota would incentivize unused wrappers, duplicate existing owners, delay small accepted outcomes, and recreate the proxy ceremony the current workflow removed.
- **Do Not Repeat Until**: Do not reintroduce an unconditional new-script quota from preference alone.
- **Evidence-Based Retry Condition**: Reconsider only if matched real consumer evidence shows that explicit Ordinary Small exemptions leave a repeated high-cost sequence unowned and that a universal requirement improves outcome-preserving friction without helper proliferation or completion delay.
