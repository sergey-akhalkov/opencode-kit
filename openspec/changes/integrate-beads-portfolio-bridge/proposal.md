## Why

`opencode-kit` already preserves raw improvement evidence, decision-material changes, session frontiers, and source-writer ownership, but it has no lightweight durable portfolio graph for admitted work across sessions. The original Kaizen Grind plan would have filled that gap with another custom `work_items` queue, while Beads already offers local issue identity, dependency readiness, assignment, duplicate relations, and Dolt history. Foundation incident `FI-BPB-KZG-20260901-01` narrows Grind to a non-portfolio execution record, allowing this bounded bridge to reuse Beads only if it proves Windows operational fit and does not become a competing lifecycle or mutation authority.
