## ADDED Requirements

### Requirement: Continuous value has one canonical philosophy owner and compact loaded application

`global/principles-of-work.md` SHALL own the complete continuous reusable-value principle. `global/AGENTS.md` SHALL contain only the compact operational application needed by loaded main, and maintained project-facing instructions SHALL carry only their portable role-specific delta. The loaded rule SHALL compose current semantic-owner, reuse, direct-proof, parent-integration, validation, and completion owners rather than define a competing workflow.

Deterministic instruction validation SHALL check canonical ownership, required compact routing, prohibited registry/checklist/value-metric behavior, maintained mirror composition, and proof inventory shape. It SHALL NOT infer semantic value, demand, documentation truth, runtime behavior, or portability from prose markers.

#### Scenario: Canonical value principle changes

- **WHEN** a maintainer changes the complete product, foundation, or knowledge value lifecycle
- **THEN** the complete rule SHALL remain in `global/principles-of-work.md` and loaded/project mirrors SHALL contain only the smallest required application
- **AND** exact-duplication validation rejects a second complete owner.

#### Scenario: Compact loaded rule is missing

- **WHEN** the canonical principle exists but loaded main lacks first-consumer, production-reachability, retirement, or non-completing-progress application
- **THEN** structural instruction validation SHALL fail with the missing owner or routing fact
- **AND** it does not claim that adding a marker proves model behavior.

#### Scenario: Proposed instruction adds a registry or mandatory receipt

- **WHEN** a maintained active instruction requires a central capability registry, demand ledger, value score, universal search receipt, or retained value-progress artifact
- **THEN** validation SHALL reject the competing behavior
- **AND** ordinary source foraging and existing reuse routing remain canonical.

### Requirement: Installed behavior proves proportional continuous-value decisions

The instruction change SHALL extend existing matched same-model proof families rather than add a second generic runner. The reviewed installed population SHALL include a first-consumer owner-local capability with direct and parent proof, a second consumer reusing it, last-consumer retirement, one cohesive direct implementation, one trivial fix, current and stale knowledge controls, and unrelated projects with and without a fitting native analyzer.

Evidence SHALL preserve prompt and scenario identity, configured source/model/profile/environment, permissions, tool events, changed-file/effect manifests, direct and parent observations, value-progress-fact presence or absence, reachability/freshness result, validation, diagnostics, cleanup, and maximum claim. Provider-free reachability fixtures SHALL remain separate from configured model behavior evidence.

#### Scenario: First consumer becomes visible without completing the root

- **WHEN** a matched installed scenario completes one reusable capability while a required parent dependency remains open
- **THEN** loaded main SHALL report the capability consumer and proof boundary through one bounded ordinary progress or handoff fact
- **AND** it preserves the root as incomplete.

#### Scenario: Second consumer uses the existing owner

- **WHEN** the installed candidate receives a later accepted case with the same verified contract and effect envelope
- **THEN** it SHALL reuse the current capability through its semantic owner
- **AND** it does not create a sibling, registry entry, promotion step, or mandatory search report.

#### Scenario: Trivial fix stays proportional

- **WHEN** the installed candidate receives a trivial owner-local correction with no truthful reusable capability boundary
- **THEN** it SHALL use direct run-observe-correct without loading extra discovery detail
- **AND** it emits no synthetic value progress fact or knowledge artifact.

#### Scenario: Static markers pass but behavior substitutes output for value

- **WHEN** deterministic instruction checks pass but an installed candidate reports a helper or green component check as delivered foundation value without a production consumer and parent integration
- **THEN** behavior evaluation SHALL reject the candidate
- **AND** structural success does not satisfy the `CRVD-001` behavior claim.
