## Context

See `proposal.md` for motivation and the `OPDC-001` claim. The current kit already has the required component owners: global principles name Theory of Constraints and Kaizen; loaded main and OpenSpec apply own autonomous process correction; stagnation/history prevent repeated mechanisms; Change-Ready owns costly proof, dependency-scoped invalidation, and live-attempt diagnosis; behavioral-substitution qualification owns caching, batching, replay, skip, and replacement claims; grind owns task-scoped process gates; compaction owns continuation; and Kaizen owns optional reusable feedback.

The missing case lies between those owners. Different late defects can evade the materially-similar retry trigger, while a high observed repeated setup cost is not itself a blocker. Compaction can describe the problem only after context rollover, and Kaizen deliberately cannot alter the current task. The solution therefore extends current owners with one shared semantic checkpoint contract instead of introducing a scheduler, scorer, persistence service, specialist role, or second strategy ledger.

Both predecessor owners are now archived: `2026-08-30-make-grind-blockers-task-scoped` established the task-scoped frontier and `2026-08-30-add-cross-project-kaizen-loop` established non-authorizing Kaizen capture plus compaction/archive composition. Their writers are terminal, the current canonical specs and source remain compatible with this change's accepted outcome, and this change now owns only the exact transferred roots. A separate planning-only Nuphus change names `tools/proofs/README.md`; OPDC removes that unnecessary write and reuses the already registered consumer-outcome proof family without touching the shared inventory file.

## Goals / Non-Goals

**Goals:**

- Trigger one bounded route reconsideration from project-neutral evidence before another dependent costly action.
- Cover different-defect late-discovery and dominant-cost patterns without weakening existing stagnation or live-attempt rules.
- Keep process changes autonomous and product/proof-scope changes owner-owned.
- Reuse ordinary session state, OpenSpec history/planning, grind frontier, and compaction instead of adding persistence.
- Prove trigger discrimination and route behavior in unrelated projects and task classes.

**Non-Goals:**

- A periodic timer, productivity score, duration budget, optimizer agent, automatic triage campaign, or deterministic semantic classifier.
- A new on-demand skill, command, plugin tool, event store, proof database, or cross-project writer.
- Automatic implementation of consumer-project optimizations beyond the current accepted task and authority.
- Any guarantee that the selected route is globally optimal or that intrinsic required work becomes faster.

## Decisions

### 1. Extend existing owners without a new runtime mechanism

Add the compact universal activation rule to the always-loaded main authority and place role-specific deltas in OpenSpec apply, compaction continuity, and grind frontier instructions. The new capability spec is the single detailed semantic owner. Existing Change-Ready and behavioral-substitution skills remain referenced owners for their exact boundaries; no new delivery-checkpoint skill is introduced in this increment.

Reuse disposition: `extend`. Current-repository discovery found complete owners for retry history, proof topology, process autonomy, compaction, task-scoped gates, and cross-project feedback; only their activation and composition are missing. A new skill would add discovery, profile, duplication, and loaded-context decisions without providing stronger enforcement. Cross-project discovery is `not-applicable` because the requested target is the configured kit's global workflow and no external dependency or implementation is selected.

Alternative rejected: extend `complain` or Kaizen into current-task optimization. Their non-authorizing, non-blocking contract is intentional and prevents reusable feedback from becoming hidden implementation authority. Alternative rejected: add a dedicated optimizer subagent. The current primary already owns outcome, evidence, route selection, and integration; another model call would increase latency and split authority.

### 2. Use semantic evidence patterns, not a clock or score

Main classifies one of four additional delivery-drag patterns: different-defect late discovery, coarse invalidation amplification, failed costly repetition after only local correction, or measured dominant repeated cost. Existing similar-retry stagnation remains unchanged and can enter the same checkpoint behavior. Each classification must name the affected lane, last downstream advancement, current evidence, cost or invalidation facts, layer, and uncertainty.

No numeric time threshold is universal across compilation, hardware, network, model, migration, or proof tasks. Deterministic helpers may preserve and validate explicit observed wall times, counts, refs, and arithmetic but may not score whether cost is dominant or attempts are semantically distinct. This keeps project-neutral behavior without Goodhart pressure on task counts, response cadence, or elapsed time.

Alternative rejected: trigger after N minutes or an unchanged `N/M` count. Legitimately slow work and coarse tasks would over-trigger, while a fast repeated invalidation loop could remain invisible.

### 3. Make the checkpoint one bounded current-task action

The checkpoint is due before another dependent action in the affected costly class. Main freezes only that action, not the root. It records a compact semantic tuple:

```text
accepted outcome and invariant refs
affected dependency lane
last downstream advancement ref
pattern class and observed evidence refs
bottleneck layer and uncertainty
current repeated cost or invalidation
considered route alternatives
selected route or irreducible | unknown
dependency-scoped invalidation
next real boundary and observable oracle
suppression identity and retry condition
```

The suppression identity is model-supplied from current refs and normalized by existing deterministic boundaries where available. It prevents repeated reflection until the downstream boundary, bottleneck evidence, selected-route oracle, or accepted outcome changes. Deterministic code never derives the semantic tuple from transcript prose.

Alternative rejected: create a durable checkpoint database. Ordinary roots do not need durable scheduling, OpenSpec and grind already have state owners, and compaction already transports current continuation facts.

### 4. Select only outcome-preserving route changes autonomously

Main evaluates removal of unnecessary process work, earlier sufficient signals, current-run diagnosis, dependency isolation, automation, safe parallelism, and qualified batching/reuse. The selected route must preserve the same accepted outcome, population, oracle, independence, restoration, cleanup, authorization, and claim ceiling. Agent-authored task order, attempt count, stop line, helper boundary, and proof sequencing remain autonomous controls.

Any skip, cache, replay replacement, batching, emulation, or shared-state route that claims equivalent evidence is routed through `behavioral-substitution-qualification` before it can replace the accepted path. A reduction in accepted population or proof fidelity is a product/proof-scope decision, not process optimization. A route requiring a protected action retains its exact gate.

When no safe improvement exists, `irreducible` closes the checkpoint and permits the existing safe route; `unknown` states the missing discriminating evidence. Neither result creates another reflection cycle or an owner process-approval question.

Alternative rejected: require measurable speedup before selecting a fail-fast or automation route. Before implementation only expected causal leverage may be available; the selected route instead names a falsifiable first oracle, and later evidence decides whether it remains viable.

### 5. Persist continuity only through current owners

For OpenSpec work, `history.md` receives an entry only when a route is superseded or a materially distinct optimization is tried. Design, tasks, and proof controls change only when their current facts or dependencies change. Ordinary roots create no repository artifact solely for reflection. Grind roots represent the checkpoint as a process item or dependency in the existing frontier; controller readiness enforces ordering without semantic inference. Compaction carries an unresolved checkpoint as current dependency closure, not optional improvement. Kaizen may receive a separate reusable signal after current routing is settled.

Alternative rejected: always append a checkpoint report. That recreates mandatory retrospective ceremony and makes reflection output rather than delivery outcome the target.

### 6. Prove behavior with a reviewed project-neutral scenario pack

Extend existing instruction/compaction contract and completion-guard proof owners with one explicit seed population outside helper code. The pack covers ordinary, OpenSpec, and grind roots across at least two unrelated disposable repositories and includes positive and negative controls from `OPDC-001`. Deterministic evaluation checks required fields, event order, exact task/frontier/file effects, population preservation, absence of user questions, duplicate suppression, and cleanup; model-owned judgments remain in reviewed expected records.

The first real boundary is a configured disposable ordinary root where two different observed late failures are supplied as current facts and the candidate selects an earlier canary without changing the accepted oracle. The next boundary is an OpenSpec root that updates route controls coherently, followed by a grind root that runs an independent sibling before the due checkpoint and never emits a product question. Controls include advancing long work, one cheap failure, irreducible work, duplicate facts, and a tempting scope-reducing option.

Configured calls use the repository's standing bounded synthetic authorization, non-sensitive fixtures, isolated state, fixed population, and exact call counts. No target project remote/protected effect is performed. Every proof-owned process/session is closed and disposable roots and temporary output are removed.

### 7. Acquire serialized ownership from archived predecessors

The ownership manifest records archived transfers from `make-grind-blockers-task-scoped` for global main, OpenSpec apply, frontier/completion, and shared proof owners, and from `add-cross-project-kaizen-loop` for global main, compaction template, and consumer-outcome proof owners. Apply re-read both archived results, current canonical specs, active source, and ownership state before enabling mutation. `tools/proofs/README.md` is not acquired because the existing consumer-outcome inventory entry remains sufficient and another planning change names that file.

If later current evidence changes the assumed frontier, compaction, or Kaizen contract, update this change's smallest coherent proposal/spec/design/tasks set before dependent implementation. This remains an outcome-preserving planning correction, not an owner decision.

## Failure Boundaries And Diagnostics

- Trigger classification: preserve pattern class, affected lane, last downstream advancement, observed attempts/costs, and uncertainty; unsupported evidence remains `unknown` rather than no-trigger.
- Checkpoint execution: preserve alternatives considered, selected route, dependency invalidation, next oracle, and suppression identity without private transcript content.
- OpenSpec continuity: preserve exact changed artifact paths and history refs; failure to update coherently blocks only dependent implementation.
- Grind projection: preserve frontier generation, process item/gate refs, derived runnable refs, and rejected illegal product-decision verdicts.
- Configured proof: inspect candidate/environment/model identities, exact prompts/fixtures, calls, event order, stdout/stderr, file effects, and cleanup in the current run.

## Risks / Trade-offs

- **[Model misses or over-classifies delivery drag]** -> Use a finite reviewed positive/negative population, exact evidence fields, and installed matched comparison without claiming universal detection.
- **[Checkpoint becomes recurring ceremony]** -> Require a supported pattern, one suppression identity, no artifact by default, and no repeat without decision-changing evidence.
- **[Optimization silently weakens proof]** -> Preserve population/oracle fields and route substitution claims through the existing qualification owner.
- **[Global rule adds context cost]** -> Keep activation compact in always-loaded instructions and reference existing detailed owners rather than adding a new skill or duplicated procedure.
- **[Grind main supplies a false semantic item]** -> Controller validates only structure/readiness; arbiter and installed scenarios challenge omissions, while deterministic code never invents checkpoint meaning.
- **[Active owner overlap causes mixed candidate evidence]** -> Keep mutation disabled until both dependencies archive/transfer and rebind proof to one readable post-transfer candidate.
- **[No safe speedup exists]** -> Record irreducible/unknown and continue the required safe route; the change promises reconsideration, not universal elapsed-time reduction.
