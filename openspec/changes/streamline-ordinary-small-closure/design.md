## Context

See `proposal.md` for the observed closure friction and SOSC-001 claim boundary. The current source has three independent mechanisms that compose into the problem:

- loaded main requires team advice before most non-trivial root-route decisions;
- OpenSpec gates identify Ordinary Small through several proposal-level exemption or `none` declarations rather than one structured profile;
- validators pin complete human-readable sentences across canonical and mirrored instruction surfaces.

The current active ownership topology also matters. `add-outcome-preserving-delivery-checkpoints` is mutation-enabled and owns several affected instruction, OpenSpec, compaction, proof, and validator roots. `add-leaf-first-task-decomposition` and `prefer-composable-capability-owners` are planning-only successors with overlapping future roots. This change therefore remains planning-only until one current mutation order and exact owner transfer are materialized without changing any accepted product outcome.

The current fidelity rung is reviewed source and provider-free structural behavior. The next real boundary after ownership acquisition is one installed direct Ordinary Small scenario, not a broad qualification campaign. No external, remote, deployment, install, credential, destructive, or consumer-project effect is authorized. Disposable roots and proof-owned sessions/processes must be removed; create-new proof output remains temporary unless an existing project-native fixture owner requires reviewed seed bytes.

## Goals / Non-Goals

**Goals:**

- Make direct main-owned execution the default whenever no concrete specialist-selection uncertainty exists.
- Replace multiple no-op OpenSpec declarations with one reviewed machine-readable profile.
- Keep legacy and Material records fail-closed and readable.
- Validate parser syntax structurally and workflow behavior through focused fixtures rather than complete prose sentences.
- Reach the first installed real boundary before expanding the finite SOSC-001 population.

**Non-Goals:**

- Do not remove the advisor, catalog, Practice Owners, OpenSpec, runtime proof, or archive task-completeness checks.
- Do not solve campaign, exhaustive-audit, evidence-retention, or general CI duplication in this change.
- Do not add a new agent, skill, workflow database, semantic classifier, scoring system, or second profile taxonomy.
- Do not rewrite active or archived proposal bytes solely to adopt the new profile.

## Decisions

### 1. Use one optional OpenSpec metadata profile

Extend the existing `.openspec.yaml` change metadata owner with one optional value:

```yaml
profile: ordinary-small | material
```

The value is reviewed main-owned input. Deterministic code validates only the enum and selects the corresponding artifact contract; it does not infer risk from prose, paths, file counts, task counts, or diff size.

| Metadata | Gate behavior |
|---|---|
| `profile: ordinary-small` | Compact proposal contract; omission of unlinked horizon, dividend, falsification, separate exact claim record, and no-event history is valid. |
| `profile: material` | Current complete capsule and applicable declaration/review checks remain required. |
| Missing | Existing legacy-strict behavior remains. |
| Invalid | Propose/apply/archive fail with the exact metadata error. |

This is smaller and safer than inferring Ordinary Small from prose, adding separate booleans for every exemption, or introducing another registry. Existing changes need no migration.

### 2. Ordinary Small omission means not applicable, not implicit semantic inference

The profile is the explicit reviewed semantic input. Under `ordinary-small`:

- proposal `Why`, `What Changes`, `Impact`, `Outcome`, `Observable Proof`, and `Stop Line` provide the compact accepted contract;
- missing Delivery Horizon means unlinked;
- missing Automation Dividend means no accepted repeated-sequence dividend;
- missing Bounded Falsification Review means the exact change has no decision-material review surface;
- Observable Proof is the exact-case claim boundary;
- absent `history.md` means no distinct strategy event occurred.

If any linked horizon, required dividend, broad claim, falsification episode, or history event is explicitly present, its existing parser and correlation checks still apply. A broad claim or Material trigger cannot remain on the compact route merely because the metadata says Ordinary Small; main must correct the profile before mutation.

Alternative rejected: keep all declarations but generate exemption text. That removes typing but preserves artifact count, synchronization, and validation coupling. Alternative rejected: default every missing profile to Ordinary Small. That would silently downgrade legacy and Material changes.

### 3. Advisor activation follows evidenced decision value

Main does not need an advisor to decide that no advisor is useful. It works directly unless current evidence identifies one of these unresolved decisions:

- two or more plausible maintained routes with materially different value or boundaries;
- one exact required capability whose availability or owner is unknown;
- independent evidence whose freshness or separation changes the decision;
- an isolated execution package whose delegation value or boundary cannot be resolved directly.

Registered Practice Owners remain independent exact-trigger routes and do not require advisor discovery. If the catalog is unavailable, only a currently required catalog-dependent choice becomes unknown; direct accepted work continues.

Alternative rejected: retain mandatory advice but cache `main-alone`. This substitutes one model result for another and still pays the first serial call. Alternative rejected: delete the advisor. It still has value for genuine team-selection uncertainty.

### 4. Exact-string checks remain only at machine boundaries

The implementation first classifies each touched marker as parser-facing syntax, stable identifier/schema value, generated fragment, or human-readable policy. The first three may retain exact validation. Human-readable policy moves to:

- one canonical semantic owner;
- structural checks for required owner, section, and stable identifiers;
- positive and negative installed/provider-free fixtures for route behavior;
- no complete-sentence synchronization across independently maintained prose.

This change removes only markers on the touched Ordinary Small/advisor/OpenSpec route. It does not launch a repository-wide validator rewrite.

### 5. Reuse existing proof owners and prove the direct path first

The automation dividend extends existing team-advising, OpenSpec operation-gate, and consumer-outcome fixtures. It rebinds the maintained STA-001 `non-trivial-single-domain-main-alone` member from one `main-alone` advisor call to direct main execution, while retaining advisor calls for concrete competing-route, capability, independent-evidence, and isolation controls. Reviewed seed data carries expected semantic judgments; deterministic helpers validate only explicit event/artifact facts.

Proof order:

1. Provider-free metadata/parser and operation-gate positive/red controls.
2. Actual installed direct Ordinary Small scenario with no advisor call, real runtime output, focused validation, and cleanup.
3. Installed advisor-value and triggered Practice Owner controls.
4. Minimal Ordinary Small OpenSpec path plus Material, malformed-profile, and representative legacy controls.
5. Complete finite SOSC-001 evaluation and claim-ceiling readback.

No configured model call is repeated after an evidence-only failure until the preserved run reaches terminal provider-free replay or identifies the exact missing raw observation.

### 6. Reconcile active owners before production mutation

The scaffold carries `mutationEnabled=false`. The first apply task must wait for the current mutation-enabled checkpoint change to archive with terminal writers, then reread all three active ownership manifests, current source, canonical specs, and runtime identities. Main may reorder planning-only dependencies and transfer exact owners as an outcome-preserving process correction, but it may not silently cancel or alter another change's accepted behavior. Exactly one change may own each overlapping production/proof root before this change mutates it.

Alternative rejected: mutate only apparently free files now. That would create a mixed loaded candidate and invalidate later routing proof. Alternative rejected: wait to write any planning artifact. The user explicitly requested this spec, and a mutation-disabled proposal records the accepted reduction without claiming write authority.

## Risks / Trade-offs

- **[Profile is misdeclared Ordinary Small]** -> Main retains Material trigger authority; broad/Material controls include red fixtures; invalid or absent metadata fails strict; apply stops before behavior mutation when current evidence contradicts the profile.
- **[Legacy proposal breaks]** -> Missing metadata uses the current strict contract; representative active and archived records remain parser fixtures.
- **[Removing phrase checks hides semantic drift]** -> Retain stable syntax checks and require positive/negative route behavior; do not remove a marker until its replacement oracle fails on a deliberate defect.
- **[Advisor becomes underused]** -> Keep finite advisor-value positive controls and reject candidates that miss a uniquely useful package.
- **[New metadata is another ceremony]** -> One enum replaces several repeated declarations and empty files; it is not copied into proposal/design/tasks.
- **[Active planning order churns]** -> Keep all production mutation disabled until current identity and owner transfer are conflict-free; planning-order edits preserve accepted outcomes and require no new product decision.
- **[Configured model behavior is population-limited]** -> Keep the SOSC-001 maximum claim finite and preserve provider-free red controls; do not generalize to all models or repositories.

## Migration Plan

1. Archive and close the current mutation-enabled predecessor or remain blocked without production edits.
2. Reconcile active planning-only ownership and select one acyclic transfer order for the affected roots.
3. Add optional metadata parsing with missing-as-legacy behavior and focused compatibility fixtures.
4. Change routing and artifact requirements behind the new profile, then run the proof order above.
5. Remove only superseded exact prose markers after their replacement behavior oracles demonstrate red/green discrimination.
6. Rollback by disabling new profile selection and restoring the prior routing/gate branch; legacy records and canonical specs remain readable throughout.
