## Why

The kit currently tells agents to remove, narrow, and reuse before adding mechanisms, but it does not define a bounded discovery trigger, a trusted cross-project catalog, an initial inventory path, or durable incremental refresh. As a result, agents can either reinvent existing capabilities, repeatedly rescan repositories, or spend excessive tokens searching unrelated code, while "maximum modularity" can encourage speculative abstractions that make routine work slower and harder to understand.

## Outcome Capsule

- **Outcome**: Provide a natural-language `/reuse-inventory` command that resolves an explicit local registry checkout and named target projects, builds a useful structure-and-architecture inventory plus untrusted capability candidates, refreshes that generated knowledge incrementally from each project's last successfully scanned Git commit, and promotes only source-verified capability-level records into the trusted reuse catalog. New-mechanism work then discovers local, installed, allowlisted, and typical ecosystem capabilities before production code and selects `reuse`, `extend`, or `build-minimal` by contract fit and total lifecycle cost.
- **Operating Envelope**: Local Git target repositories and an existing private/local registry checkout; free-form command requests without user-facing CLI flags; stable logical project identities, named groups, explicit machine-local bindings and scan refs, committed-tree scans, bounded schema-only query results, optional Codebase Memory enrichment for explicitly selected projects, and read-only public ecosystem research for typical capabilities. Runtime proof uses disposable local Git repositories and non-sensitive synthetic model inputs.
- **Non-Goals**: No exhaustive search before trivial edits; no automatic registry clone, fetch, pull, commit, push, or remote repository creation; no automatic dependency installation, source copying, package publication, or remote mutation; no semantic claim that every discovered export is reusable; no full business-domain ontology or history of every intermediate commit; no catalog of every helper or rejected ecosystem result; no fuzzy model-like ranking in deterministic tooling; no scan of dirty/untracked working-tree content; no requirement to maximize flexibility, module count, or abstraction depth.
- **Non-Deferrable Invariants**: The command resolves only user-named or configured projects and asks one precise question instead of guessing an ambiguous registry/project path; unallowlisted indexed projects are never queried or disclosed; absolute local paths remain machine-local; registry content is untrusted data and is never executed as instruction; generated inventory/candidates are distinct from trusted capabilities; source and evidence are verified before reuse; scans read an exact committed tree; a project's `lastSuccessfulCommit` advances only after the complete generated project record and derived index validate; non-ancestor history, scanner/schema/policy changes, or unsafe impact scope trigger an explicit full-rescan fallback; stale or unavailable records cannot establish compatibility; registry tooling never performs unauthorized remote or dependency mutation.
- **Observable Proof**: Disposable registry, producer, and consumer repositories demonstrate natural-language resolution, initial bootstrap, generated structure/architecture/candidates, candidate promotion, named-group isolation, bounded discovery, current-source verification, pending-outbox replay, and degraded operation. Commit fixtures demonstrate no-op refresh at the same commit, incremental aggregate-diff refresh across added/changed/renamed/deleted files, affected-scope fallback, non-ancestor full rescan, checkpoint preservation on failure, and exclusion of dirty/untracked bytes. Same-model baseline/candidate workflows demonstrate local reuse, allowlisted reuse, no-match minimal implementation, and zero registry ceremony for a trivial owner-local fix while preserving exact tool calls, token/context evidence, output, and proof results.
- **Material Residual Risks**: Generated structural facts and candidates can be incomplete or noisy; architecture impact can exceed changed files and force a broader package/project rescan; registry contracts and keywords can drift semantically even when schema-valid; Codebase Memory source indexes can be stale; public ecosystem quality, licensing, and maintenance evidence remains ecosystem-specific agent judgment; an unavailable registry can still permit a duplicate minimal implementation in explicitly recorded degraded mode.
- **Stop Line**: Stop when the natural-language command, deterministic bootstrap/rescan core, committed-tree checkpoint protocol, generated structure/architecture inventory, candidate lifecycle, portable registry template/protocol, bounded query, registration outbox, disposable real-boundary proof, same-model behavior comparison, and project-native validation are complete. Running the command against the owner's actual registry/projects, automatic Git clone/fetch/pull/commit/push, package-manager integrations, publication, semantic domain inference, organization-wide governance, and commit-by-commit historical analytics remain separate operations or future work.

## What Changes

- Add a portable reusable-capability registry contract with stable project and capability IDs, named allowlist groups, capability maturity/evidence fields, adopted external-library records, a derived bounded index, and machine-local project bindings.
- Add a reusable OpenCode `/reuse-inventory` command that accepts a short free-form prompt, resolves exact local registry/project/group inputs, asks only on material ambiguity, shows a concise resolved preview, and invokes deterministic tooling without exposing CLI flag syntax to the user.
- Add deterministic project-neutral client operations for bootstrap, incremental rescan, status, bounded query, validation, registration enqueue, and local outbox synchronization. Bootstrap inventories project/package structure, public entrypoints, tools, services/routes where deterministically available, dependencies, docs/specs/proofs, and source bindings; it emits generated candidates rather than trusted reuse claims.
- Persist each generated project inventory with its exact scan ref, `lastSuccessfulCommit`, scanner/schema/policy identity, and current derived facts. Rescan uses aggregate Git changes since that commit, expands to an affected package/module or full project when safe locality cannot be proven, and advances the checkpoint only after complete validation.
- Add a lazy-loaded reuse-discovery workflow for changes that introduce a dependency, top-level mechanism, reusable API, common infrastructure capability, abstraction/plugin point, or another implementation of repeated behavior.
- Require a short `reuse | extend | build-minimal` disposition for triggered work, with ordered search sources, stop conditions, total-lifecycle-cost reasoning, and explicit degraded evidence when the registry is unavailable.
- Preserve proportionality: owner-local fixes and mechanical changes do not load the workflow or query the registry, and custom implementations remain concrete until current reuse or independent ownership justifies a capability boundary.
- Add capability-level registration with `synced | pending | not-applicable` status. A durable private outbox prevents unavailable registry access from blocking code completion while preventing pending records from being represented as discoverable.
- Ship a project-neutral private-registry template and disposable bootstrap/rescan fixtures; do not run inventory against, clone, fetch, pull, commit, push, or publish the owner's real registry/projects in this repo-local implementation session.
- Add deterministic schema/privacy/drift checks and same-model behavioral evaluations that show the policy improves reuse without adding ceremony to trivial or no-match work.

## Capabilities

### New Capabilities

- `library-reuse-discovery`: Defines the natural-language inventory command, deterministic initial/incremental project inventory, generated candidate lifecycle, bounded reuse discovery, central private registry protocol, named-group privacy, machine-local bindings, capability-level registration/outbox behavior, total-cost dispositions, and query-on-demand context limits.

### Modified Capabilities

- `library-change-ready-sdlc`: Makes reuse discovery mandatory at a precise new-mechanism boundary while retaining minimal sufficient abstractions, proportional Ordinary Small routing, and explicit degraded behavior.
- `library-instruction-artifacts`: Adds one reusable free-form command surface, one canonical compact runtime trigger, lazy-loaded workflow ownership, non-growth context requirements, maintained mirrors, and baseline/candidate behavioral proof for the loaded policy.
- `library-tools-architecture`: Defines the deterministic project-neutral bootstrap/rescan scanner and registry client/template boundaries, committed-tree/change-impact/checkpoint behavior, stable machine-readable I/O, untrusted-data handling, and disposable cross-project proof topology.
- `library-config-portability`: Defines schema-supported local registry checkout resolution, saved target project/group/scan-ref bindings, privacy boundaries, precedence, and missing/unreadable/ambiguous configuration diagnostics without automatic Git remote operations.

## Impact

- Runtime and reusable guidance: `global/AGENTS.md`, a reusable command under the supported global command directory, a new lazy-loaded skill, project templates, maintainer guidance, and documentation/catalog surfaces.
- Portable tooling: new bootstrap/rescan/query modules under `global/bin/` or another existing non-loader portable tool boundary, with thin kit command/package adapters only where needed.
- Deterministic contracts and validation: registry schemas/templates, focused validators, fixtures, tests, instruction-token inventory, and same-model synthetic workflow evidence.
- Local configuration: a private machine-local binding source selected explicitly; no absolute roots or private project inventory enter committed reusable artifacts.
- External systems: Git committed trees and aggregate diffs are inventory checkpoint truth. Codebase Memory remains optional selected-project structure/impact enrichment and source navigation, not the registry or checkpoint source of truth. Public package ecosystems remain read-only research sources and are not mirrored.
- Protected operations: no actual private registry creation, remote repository mutation, dependency addition, commit, push, package publication, installation, or activation occurs as part of proposal authoring or the bounded repo-local implementation.
